# RC23 erratum (2026-10-21, written at the start of RC24)

## A. Decision-rule defect

`src/rc23_eval.py::decide` (frozen, not edited) computes:

`pass = all(x["verdict"].startswith("NON-INFERIOR") ...) and not sp["verdict"].startswith("MORE") and rob`

This has three defects:

1. The failing verdict string "NON-INFERIORITY NOT SHOWN" also starts with "NON-INFERIOR". A failed non-inferiority test therefore passed.
2. `spend_pair` returns "INCOMPLETE" when no unit is paired. That passed as "not MORE".
3. `robust_ok` only loops over the conditions it is given. A missing condition or window passed.

## C. Missing witness

RC23's validation recorded only that HA_LR stays finite when the temperature and spike channels are absent. It did not show directly that PHR_NRMAP fails. The direct witness is `../opus_rc24/correction/RC24_PHR_NRMAP_WITNESS.json`:
- On the recorded state (repeat 35, fold 1, budget 24), each construction was computed alone.
- With T absent, S absent, or both absent in every paid run, PHR_NRMAP raises `ValueError: array must not contain infs or NaNs` (in `asarray_chkfinite`).
- On the same state with all channels present, PHR_NRMAP is finite.
- HA_LEAN and HONLY_LR are bitwise unchanged.
- HA_LR stays finite but changes by up to 0.44, because its shared upstream changes.

The RC23 report sentence "PHR_NRMAP crashes if a channel is fully absent" is now directly witnessed. It concerns PHR_NRMAP only, not HA_LR.
